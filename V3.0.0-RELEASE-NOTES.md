# AnchorWeight v3.0.0 Release Notes

AnchorWeight v3.0.0 is the first stable v3 release. It graduates the RC.2 production-burn-in build without expanding the feature-frozen traffic-defense surface.

## Stable v3 contract

- Agent Identity, Agent Behavior, Client Environment 2.0, traffic dimensions, Observatory, Passport, Resource Budgets, Policy Engine, Policy Forensics, Policy Simulation, Release Readiness, and Enforcement Rehearsal remain on the RC.1 frozen contract.
- Policy actions remain: `allow`, `observe`, `budget`, `throttle`, `decoy`, `quarantine`.
- No persistence schema migration is introduced by the final release.
- No new classifier, score, policy action, or enforcement path is introduced by the final release.

## Final-release hardening

- Runtime/package version becomes `3.0.0`.
- Release channel becomes `stable`.
- `npm run final:check` composes feature-freeze and burn-in invariants.
- `npm run burnin:check` remains available after GA for production operational verification.
- Release verification continues to manifest every source file.

## Production posture

The initial v3.0.0 deployment remains shadow-first. On the current HawkHost/LiteSpeed deployment, trusted proxy mode does not receive a trustworthy sanitized original client IP. AnchorWeight therefore reports `trusted_proxy_client_ip_unavailable` and `enforcementSafe:false`.

This condition does not block the stable shadow-mode release. It remains a hard blocker on client-scoped active enforcement until the hosting proxy supplies a server-generated/sanitized original client IP.
