# AnchorWeight v3.1.0-rc.1 Release Notes

AnchorWeight v3.1.0-rc.1 is the first release candidate for the v3.1 AI-agent controls line.

## Baseline

RC.1 is built from the validated beta.2 checkpoint:

- tag: `v3.1.0-beta.2-validated`
- commit: `3472fee0bb4e46d7483b9845688b0719836a1e9a`
- public production shadow validation: PASS
- authenticated operator validation: PASS
- live AI canaries: 12/12 PASS
- Passenger restart comparison: PASS
- verdict: `READY FOR v3.1 RC REVIEW`

## Changes in RC.1

- version moves to `3.1.0-rc.1`, release channel `rc`;
- Agent Passport AI Controls descriptor moves from v9 to v10;
- additive `rcReadiness` capability describes RC safety/readiness semantics;
- production-validation descriptor explicitly publishes restart comparison availability and the RC-review requirement;
- `ai-agents:rc-check` verifies validated provenance, frozen-contract integrity, critical request-path blob identity, privacy, shadow safety, production-validator semantics, documentation and release-check wiring;
- static production-validation provenance is recorded in `V3.1-RC1-VALIDATION-RECORD.json`.

## Deliberately unchanged

- no AI request-policy behavior change;
- no provider/family mapping change;
- no verification-policy behavior change;
- no automatic activation;
- no automatic restart;
- no enforcement-control endpoint;
- AI Agent Policy enforcement remains disabled by default;
- global shadow-first safety remains intact;
- the v3 frozen contract remains unchanged.

## Known limitation

HawkHost still does not provide a trustworthy sanitized original client IP to the Node application. Client identity therefore remains degraded and client-scoped/provider-network enforcement remains fail-safe constrained. This is a warning for RC validation, not a reason to weaken identity safety.

RC.1 does not grant GA readiness or enforcement readiness.
